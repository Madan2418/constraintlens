ConstraintLens build log

A runtime framework that detects semantic constraint drift in asynchronous multi-agent AI systems. It checks that a constraint such as "refund up to $100" still means the same thing after each agent rewrites the task, and it blocks the tool call when the meaning has been lost.

Phases 0–3 complete · Phase 4 next Sessions logged: 5 Last updated 2026-11-07 Python 3.11+ · FastAPI · React

Detect

Checks every delegation boundary (publish, consume) and the pre-tool-call gate for textual drift and action violations.

Localize

Names the hop and agent that caused the drift, or the queue edge when the cause is staleness or transit loss.

Compose

Tracks user, org and system constraints together. The most restrictive one wins, and a silently dropped constraint is reported.

Enforce

Allow, warn, re-ground, block or escalate before the action runs. Every decision goes to an append-only audit log.

Benchmark

driftchain-bench: 3,000 to 5,000 labelled async delegation chains built from 6 scenarios and 9 mutation operators.

What the spec says

The worked example in §2.1 shows the failure the whole system is built around. Every structural check passes and the refund still goes through at 20× the limit:

T0 · User"Refund this customer, up to $100. Anything above needs manager approval."constraint issued
Hop 1 · Intake"Process refund for order #4471, limit $100, approval above."ENTAILED
Hop 2 · Triage · after 12 min in Redis"Customer is upset about order #4471. Resolve with a refund."TEXTUAL_DRIFT, culprit
Hop 3 · Payments"Refund order #4471 in full." → issue_refund(4471, 2000)ACTION_VIOLATION → BLOCK

Key ideas

  • Two separate failures. Textual drift (hop 2) is the early warning. An action violation (hop 3) is the actual harm. They usually happen at different hops, which is why attribution is useful.
  • Three checkpoints: PUBLISH and CONSUME are advisory or re-ground. TOOL_CALL is the only one where blocking is mandatory.
  • Tiered checker, cheapest first: T0 integrity, T1a structured args, T1b lexical, T1c NLI, then T2 LLM judge only for the uncertainty band. Embeddings are used for routing only, because "$100" and "$1000" embed almost identically.
  • The envelope is never rewritten by agents. The service keeps the authoritative constraint set, and content hashes make loss and tampering detectable.

Engineering rules I must follow

  • Hexagonal architecture. domain/ imports no FastAPI, Redis, SQLite, LLM SDK or LangGraph. An import-linter check enforces this in CI.
  • Event sourcing. The append-only log is the single source of truth. Verdicts, traces and metrics are projections rebuilt by project_all().
  • Idempotency. A verdict is keyed by (trace_id, hop_id, checkpoint), so a redelivered message can never be allowed once and blocked once.
  • Fail-safe. High-risk constraints fail closed and low-risk ones fail open with a warning. Degraded verdicts are marked as degraded.
  • Pydantic v2 everywhere, with extra="forbid" and frozen models. Coverage target is 90% on domain/, and every decision-table row gets a test.
  • Test discipline. Thresholds are tuned on val only and test is touched once. CI makes no API calls and uses ScriptedJudge.

  • Bug found by a property test: with a USD cap and an INR cap in one group, a USD amount was checked only against the USD cap. Fixed: an amount is comparable only when every bound uses its unit; otherwise the result is "incomparable", ranked as forbidden.

Reconciliation keeps the more restrictive value and flags disagreements. Modes: off / fallback (default) / always (CL_EXTRACTION_LLM_MODE). Prompt file: docs/judge_prompts/extract_v1.md.
  • OpenTrace use case (application/open_trace.py): extract, add declared org/system policies, issue, compose, refuse if unsatisfiable (and record the refusal), record TRACE_OPENED and CONSTRAINT_REGISTERED, return the root envelope. Only the instruction's hash is stored unless full text is opted in.
